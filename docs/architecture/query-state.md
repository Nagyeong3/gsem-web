# 프론트 조회 상태 관리 기준

## 목적

페이지가 Mock Adapter와 HTTP API Adapter 중 어느 구현을 사용하더라도 동일한 조회 흐름과 사용자 경험을 제공한다. 이 문서는 현재 프로토타입의 공통 기준이며 실제 서버의 캐시·취소 정책이 확정되면 보완한다.

## 의존 흐름

```text
페이지
→ useAsyncQuery 조회 Hook
→ Service 인터페이스
→ Mock Adapter 또는 HTTP API Adapter
```

페이지는 Service의 Promise를 직접 `useEffect`에서 처리하지 않는다. 조회 함수는 `useCallback`으로 고정하고 `useAsyncQuery`에 전달한다.

## 공통 상태

- `idle`: 조회 조건이 충족되지 않아 요청하지 않은 상태
- `loading`: 최초 조회 또는 조건 변경 후 새 결과를 기다리는 상태
- `success`: 최신 요청이 성공한 상태
- `error`: 최신 요청이 실패한 상태

`QueryStatePanel`은 로딩·오류·빈 결과를 동일한 아이콘, 문구 크기, 간격과 버튼 규격으로 표시한다. 오류 상태에는 가능한 경우 `다시 불러오기`를 제공한다.

## 동시 요청 처리

필터를 빠르게 변경하거나 페이지를 이동하면 이전 요청이 나중에 도착할 수 있다. `useAsyncQuery`는 요청 버전을 비교하여 최신 요청이 아닌 응답이 화면 상태를 덮어쓰지 못하게 한다.

현재 Service 인터페이스에는 `AbortSignal`이 포함되지 않아 네트워크 전송 자체를 중단하지는 않는다. 실제 백엔드 연동 계약이 확정되면 Service 메서드에 선택적 `AbortSignal`을 추가하고 HTTP Client까지 전달하는 방식을 검토한다.

## 화면별 적용 원칙

- 대시보드: 전체 조회 실패 시 페이지 제목을 유지하고 재시도 화면을 표시한다.
- 장비 검색: 필터·정렬·페이지 변경 시 기존 결과를 보존하되 조회 영역에 로딩 상태를 표시한다.
- 장비 상세: 잘못된 식별자·존재하지 않는 품목과 서버 오류를 구분한다.
- 납품 일정·변경 신청: 목록 조회 상태를 표 영역 안에서 표시하고, 선택 상세는 최신 목록에서 파생한다.
- 장비 변경 이력: 그래프 조회 오류와 필터 결과 없음 상태를 그래프 영역에서 구분한다.

## 미확정 사항

- 서버 캐시 유지 시간과 재검증 정책
- 요청 취소를 위한 `AbortSignal` 계약
- 오류 코드별 사용자 문구와 재시도 가능 여부
- 인증 만료 및 권한 오류의 전역 처리 방식
