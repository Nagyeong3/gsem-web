# 지원장비 관리시스템 요구사항 초안

## 1. 문서 목적

이 문서는 1차 요구사항 검토 결과와 촬영된 요구사항 초안을 바탕으로 현재까지 파악한 내용을 정리한 기준 문서다.

아직 확정되지 않은 업무 규칙을 임의로 확정하지 않으며, 요구사항 회의 결과에 따라 계속 수정한다. 실제 품번, 직원 정보, 연락처, 계약정보 등 사내 정보는 저장소에 기록하지 않는다.

## 2. 상태 구분

- **확정**: 현재까지 사용자가 명시적으로 확인한 내용
- **부분 확정**: 기능의 목적은 확인됐지만 세부 규칙이 미정인 내용
- **미확정**: 추가 업무 검토가 필요한 내용
- **후순위**: 요구사항에는 존재하지만 1차 프로토타입에서 우선 구현하지 않는 내용
- **제외**: 불완전하여 현재 분석 범위에서 제외한 내용

## 3. 시스템 목적

지원장비 관련 정보를 통합 조회하고 납품 및 변경 이력을 추적한다.

예상 업무 범위는 다음과 같다.

- 자료 입력 및 현황 조회
- 통합 검색, 필터링 및 정렬
- 납품 일정과 진행 상태 관리
- 단종품과 대체품 관계 추적
- 정보 및 담당자 변경 이력 보존
- 리포트 생성과 사용자 알림
- 관련 정보의 통합 조회

## 4. 예상 사용자

- 일반 조회자
- 지원장비 담당자
- 구매 담당자
- 승인자

실제 인증·인가 방식과 역할별 권한은 아직 확정되지 않았다.

## 5. 1차 프로토타입 범위

### 포함

1. 메인 대시보드
2. 장비 검색 및 상세 조회
3. 납품 일정과 진행 현황 표현
4. 장비 변경 이력
5. 단종품·대체품 계보 트리
6. 상세 변경 로그 팝업 또는 드로어
7. 목업 데이터를 사용한 검색·필터·정렬·화면 상태

### 제외

- 실제 로그인
- 실제 데이터베이스 연동
- 실제 변경 승인 처리
- 실제 엑셀 다운로드
- 운영용 메일 발송
- 운영용 문서 저장 및 연계

## 6. 핵심 업무 규칙

현재까지 확인된 핵심 규칙은 다음과 같다.

- 한 품목은 여러 사업에 포함될 수 있다.
- 한 장비는 여러 기종과 계통에 적용될 수 있다.
- 하나의 단종 장비에 여러 대체품이 연결될 수 있다.
- 대체 관계는 일대일 관계로 단정하지 않는다.
- 변경 이력은 변경 전·후 내용과 처리 과정을 추적할 수 있어야 한다.
- 실제 관계 구조와 상태 전이 규칙은 추가 회의 후 확정한다.

## 7. 요구사항 목록

### 요구사항 001: 체계·양산 간 연관 품번 조회

**상태: 부분 확정**

체계개발과 양산에서 서로 다르게 부여된 관련 품번을 연결하여 조회할 수 있어야 한다. 사용자가 한쪽 품번만 알고 있어도 관련 장비와 품번을 찾을 수 있어야 한다.

동일품, 파생품, 대체품 등 관계 유형의 세부 구분은 추후 확정한다.

### 요구사항 002: 장비 구매 이력 통합 조회

**상태: 부분 확정**

서로 다른 기존 시스템에 분산된 구매 및 품질 관련 정보를 장비를 기준으로 통합 조회할 수 있어야 한다.

구체적인 연계 대상, 조회 항목, 시스템 연계 방식은 추후 확정한다.

### 요구사항 003: 획득 가능·단종 상태 조회

**상태: 부분 확정**

지원장비가 현재 획득 가능한지 또는 단종되어 획득이 불가능한지 확인할 수 있어야 한다.

상태 등록 주체, 판정 근거, 확정 절차는 추후 결정한다.

### 요구사항 004: 적용 기종 복수 관리

**상태: 확정**

하나의 장비에 여러 적용 기종을 등록할 수 있어야 하며, 기종별로 적용 장비를 검색할 수 있어야 한다.

### 요구사항 005: 영문 SERD 생성 지원

**상태: 부분 확정**

한글로 관리되는 SERD 정보를 수출용 영문 SERD로 작성할 수 있도록 지원해야 한다. 자동번역의 적용 범위, 검토 절차, 표준 번역 관리 방식은 추후 결정한다.

### 요구사항 006: 선택 항목 데이터 추출

**상태: 부분 확정**

전체 데이터가 아닌 사용자가 필요한 항목과 범위를 선택하여 추출할 수 있어야 한다. Section별 선택과 출력 항목 저장 여부는 추후 결정한다.

### 요구사항 007: 변경 이력 상세 등록

**상태: 부분 확정**

지원장비 정보 변경 시 변경 일자, 변경 사유, 변경 근거 등 상세 내역을 기록하고 조회할 수 있어야 한다.

최소 검토 항목은 다음과 같다.

- 변경 일자
- 변경 항목
- 변경 전 값
- 변경 후 값
- 변경 사유
- 변경 근거
- 요청자와 처리자
- 처리 상태

필수 입력 항목과 승인 절차는 추후 확정한다.

### 요구사항 008: 관리 품목 유형 확장

**상태: 확정**

다음 항목을 각각 데이터베이스 관리 대상으로 포함해야 한다.

- 지원장비
- 기본불출품목
- 조종장구류 점검장비
- 표준기

사용자는 검색 화면에서 품목 유형을 기준으로 필터링하여 원하는 항목을 찾을 수 있어야 한다.

각 유형을 별도 테이블로 분리할지 공통 품목 구조로 관리할지는 데이터 분석과 DB 설계 과정에서 결정한다.

### 요구사항 009: 사업별 납품 진행 현황

**상태: 부분 확정**

현재 진행 중인 사업의 납품 대상 품목, 납지, 일정, 수량 및 진행 상황을 조회할 수 있어야 한다.

정확한 납품 단계와 상태값은 추후 확정한다.

### 요구사항 010: 품목별 담당자 변경 이력

**상태: 확정**

지원장비 품목별 현재 담당자와 과거 담당자 변경 이력을 조회할 수 있어야 한다.

프로토타입의 직급 표기는 책임과 선임만 사용한다.

### 요구사항 011: 품번 중심 통합 조회

**상태: 부분 확정**

품번 하나를 검색하면 해당 장비의 주요 정보를 통합 조회할 수 있어야 한다.

예상 조회 대상은 다음과 같다.

- 적용 프로젝트 또는 사업
- 납품 수량
- 납품 진행 상태
- 품명과 형상정보
- 관련 정보와 첨부자료
- 담당자
- 구매·변경·단종·대체 이력

상세 화면의 최종 항목은 데이터 식별 과정에서 확정한다.

### 요구사항 012: 개인별 조회 화면 설정

**상태: 부분 확정**

사용자가 필요한 카테고리, 표 컬럼 및 검색 조건을 구성하고 개인별로 저장할 수 있어야 한다.

실제 로그인 기능은 1차 프로토타입 범위에서 제외하므로 목업 사용자 기준으로 화면만 검증한다.

### 요구사항 013: 엑셀·PDF 출력

**상태: 부분 확정 / 1차 실제 동작 제외**

검색 결과와 업무 자료를 엑셀 또는 PDF 형태로 출력할 수 있어야 한다. 출력 양식의 구성 및 사용자별 커스터마이징 범위는 추후 결정한다.

### 요구사항 014: 동일 장비의 기종·사업별 적용 조회

**상태: 확정**

동일 지원장비에 적용되는 여러 기종과 여러 사업을 조회할 수 있어야 한다. 장비와 사업의 관계를 단일 값으로 제한하지 않는다.

### 요구사항 015: 품번·품명 통합 검색

**상태: 확정**

지원장비의 품번, 품명 등의 정보로 검색할 수 있어야 한다. 부분 일치, 연관 품번, SERD 번호 등 상세 검색 범위는 추후 확정한다.

### 요구사항 016: 복수 계통 적용 조회

**상태: 확정**

하나의 지원장비가 여러 계통에 적용되는 경우 모든 적용 계통을 등록하고 조회할 수 있어야 한다. 계통을 기준으로 관련 장비를 역검색할 수 있어야 한다.

### 요구사항 017: 제조사·구매처·담당자 관리

**상태: 부분 확정**

지원장비의 제조사, 구매처 및 담당자 정보를 관리하고 정보 변경 시 수정할 수 있어야 한다. 변경 이력, 연락처 공개 범위 및 개인정보 처리 기준은 추후 결정한다.

### 요구사항 018: 지원장비별 품보 형태

**상태: 확정**

지원장비별 품보 형태를 관리하고 조회할 수 있어야 한다.

현재 요구사항은 이 범위까지만 확정하며 품보 형태의 종류, 사업별 차이, 변경 이력 등은 추가하지 않는다.

### 요구사항 019: 교정 정보 관리

**상태: 부분 확정**

지원장비별 교정 주기와 사내 교정 가능 여부를 관리해야 한다. 사외 교정 대상인 경우 교정소 관련 정보를 함께 확인할 수 있어야 한다.

교정 상태, 만료 알림, 이력 범위는 추후 결정한다.

### 요구사항 020: 엑셀 Import·Export

**상태: 부분 확정 / 1차 실제 동작 제외**

엑셀 형태로 데이터를 가져오고 내보낼 수 있어야 한다. 대량 등록·수정 여부, 검증 규칙 및 오류 처리 방식은 추후 결정한다.

### 요구사항 021: 구매품 단종 조사

**상태: 후순위**

구매품의 단종 여부를 조사하고 결과를 관리하는 기능을 향후 구현한다.

### 요구사항 022: 개발품 관련 자료 관리

**상태: 후순위 / 용어 미확정**

개발품의 3S, 도면 등 개발 관련 자료를 관리한다. 3S의 정확한 의미와 자료 관리 방식은 추후 확인한다.

### 요구사항 023: 구매품 관련 자료 관리

**상태: 후순위**

구매품의 Datasheet 등 관련 자료를 관리한다.

### 요구사항 024: 개발 과정 생성 자료 관리

**상태: 후순위**

개발품의 개발 과정에서 생성된 PDR, CDR, TRR, DT/OT 수검자료, 개발 제품 관련 자료, 장비별 회의자료 등을 관리한다.

사진 판독 과정에서 언급됐던 ‘코딩’은 요구사항이 아니며 개발한 제품을 의미한다.

### 요구사항 025: 수리·하자·형상변경 이력

**상태: 후순위**

장비별 수리 이력, 하자 이력 및 형상변경 이력을 관리한다. 관련 서류의 저장 방식은 현재 우선순위에서 제외한다.

### 요구사항 026: 제조업체 단종 확인 메일

**상태: 부분 확정 / 1차 실제 동작 제외**

보유 중인 장비의 단종 여부를 제조업체에 확인하는 이메일 발송 기능이 필요하다.

메일 양식, 발송 조건, 회신 관리 및 자동화 범위는 추후 결정한다.

### 요구사항 027 이후

**상태: 제외**

현재 요구사항이 불완전하므로 분석 및 1차 프로토타입 범위에서 제외한다. 내용이 구체화된 이후 별도로 반영한다.

## 8. 서류 관련 요구사항 처리 원칙

문서 및 서류 관리 요구사항은 존재하지만 현재 우선순위가 높지 않으므로 상세 설계를 보류한다.

현재 단계에서는 다음 사항을 결정하지 않는다.

- 파일을 지원장비 관리시스템에 직접 업로드할지 여부
- 기존 사내 문서관리시스템 연계 여부
- 공유폴더 경로 또는 링크만 관리할지 여부
- 문서 버전, 보안, DRM 및 저장 용량 정책

프로토타입에서는 문서 기능을 핵심 화면의 중심 기능으로 구현하지 않는다.

## 9. 현재 미확정 사항

- 체계·양산·수출 품번 관계 유형과 연결 기준
- 정확한 납품 진행 단계와 상태값
- 단종·대체 정보의 등록자와 확정자
- 3S의 업무상 의미
- 요구사항 027 이후의 상세 내용
- 실제 사용자 권한과 승인 흐름
- 운영 데이터 보존 기간
- 기존 시스템 및 데이터 연계 범위

## 10. 다음 검토 순서

1. 요구사항별 실제 사용자 행동을 유즈케이스로 정리
2. 1차 프로토타입에서 검증할 행동과 제외할 행동 구분
3. 각 화면의 입력값, 출력값, 상태 및 예외 상황 정의
4. 마스터 파일에서 필요한 데이터 항목 식별
5. 목업 데이터 구조와 화면 계약 정의
6. 정적 시안 기준으로 인터랙티브 프로토타입 구현
7. 2차 요구사항 회의에서 프로토타입을 사용해 피드백 수집
8. 확정된 요구사항을 기준으로 API와 데이터베이스 설계 보완

## 11. 변경 원칙

요구사항이 수정되면 기존 내용을 조용히 덮어쓰지 않고 변경 이유와 결정 상태를 함께 기록한다. 업무 용어가 불명확한 경우 임의로 일반화하지 않고 미확정 상태로 유지한다.
