# 추가 정적 시안 재검수 결과

> 2026-07-31 재검수: 기존 문서에는 세 화면이 통과한 것으로 기록돼 있었으나,
> 실제 원본 이미지를 다시 확인한 결과 정렬 불균형과 내부 잘림이 발견됐다.
> 기존 판정을 철회하고 정적 렌더러 재구성, 재렌더링, 육안 검수 및 DOM
> 오버플로 검사를 수행한 결과를 아래에 기록한다.

## 1. 검수 대상

| 화면 | 파일 | 최종 해상도 | 결과 |
|---|---|---|---|
| 장비 통합 상세 | `docs/mockups/extended/equipment-detail.png` | 1440×900 | 재검수 통과 |
| 납품 일정 관리 | `docs/mockups/extended/delivery-schedule.png` | 1440×900 | 재검수 통과 |
| 변경 신청 및 처리 현황 | `docs/mockups/extended/change-request.png` | 1440×900 | 재검수 통과 |

## 2. 제작 방식

- 재현 가능한 정적 렌더러를 `tools/mockup-renderer/`에 추가하고 동일한
  HTML·CSS 디자인 토큰으로 세 화면을 다시 제작했다.
- 실제 React 애플리케이션 코드는 구현하지 않았다.
- `Noto Sans KR Variable`을 렌더링 전용 한글 글꼴로 사용했다.
- 아이콘은 Lucide 계열의 선형 SVG 스타일로 통일했다.
- 최종 PNG는 Chromium에서 1440×900, 배율 1로 렌더링했다.

## 3. 공통 프레임 검수

| 항목 | 검수 결과 |
|---|---|
| 캔버스 | 세 화면 모두 1440×900 |
| 사이드바 | 너비 176px, 좌표와 배경 일치 |
| 상단 헤더 | 높이 58px, 구성과 정렬 일치 |
| 콘텐츠 시작점 | X 200px, Y 76px 기준 일치 |
| 공통 여백 | 좌우 24px, 주요 Section 간격 14~16px |
| 메뉴 구성 | 대시보드, 장비 검색, 변경 이력, 변경 신청 |
| 선택 메뉴 | 화면의 진입 맥락에 맞는 메뉴만 파란색으로 표시 |

브라우저 DOM 좌표를 측정한 결과 세 화면 모두 사이드바 `176×900`,
상단 헤더 `1264×58`, 본문 프레임 `1264×842`로 일치했다.

## 4. 타이포그래피 검수

- 페이지 제목: 25px, 굵기 700
- 설명: 12px
- 카드 제목: 15px, 굵기 700
- 본문: 13px
- 표 헤더·본문: 11~12px
- 동일 컴포넌트에 동일한 크기·굵기·색상을 적용했다.
- 세 화면을 원본 해상도로 열어 한글 표시를 확인했다.
- 깨진 한글, 한자, 일본어 및 맥락 없는 외국어가 없음을 확인했다.
- 사용자명이 `김책임`으로 유지되는 것을 확인했다.
- `사원`, `대리`, `과장` 직급이 없음을 확인했다.

## 5. 색상 및 컴포넌트 검수

- 짙은 남색 사이드바와 파란색 선택 메뉴를 기준 시안과 동일한 구조로 적용했다.
- 기본 카드·입력창의 테두리, 모서리 반경, 내부 여백을 공통 토큰으로 적용했다.
- 파랑, 초록, 주황, 빨강 상태색만 사용했다.
- 상태색과 함께 텍스트 배지를 표시해 색상만으로 상태를 전달하지 않았다.
- 과도한 그림자, 글래스모피즘, 장식용 그라데이션, 이모지를 사용하지 않았다.
- 모달이 없는 화면이므로 일반 카드에는 그림자를 사용하지 않았다.

## 6. 내용 검수

### 장비 통합 상세

- 품번·품명, 품목 유형, 상태, 기본정보, 복수 기종·사업·계통을 표시했다.
- 담당자, 제조사·구매처, 품보 형태, 교정, 주요 납지, 최근 변경, 대체 관계 요약을 포함했다.
- 실제 업무정보 대신 익명 목업값을 사용했다.
- 관계 유형과 사업별 대체 기준이 미확정임을 화면에 명시했다.

### 납품 일정 관리

- 기간, 사업, 기종, 납지, 상태 필터를 포함했다.
- 계획·입고·납품 수량, 예정일, 지연 여부, 담당자를 표시했다.
- 선택 일정의 수량과 진행 단계를 우측 상세영역에 표시했다.
- 실제 납품 단계가 아닌 `프로토타입 가정`임을 명시했다.

### 변경 신청 및 처리 현황

- 신청번호, 대상 품번, 품명, 변경 유형, 신청자, 신청일, 상태, 처리자를 표시했다.
- 선택 신청의 변경 전·후, 사유, 근거, 처리 과정을 표시했다.
- 실제 승인 기능을 구현하거나 승인 작업을 강조하지 않았다.
- 상태명과 처리 단계가 프로토타입 가정임을 명시했다.

## 7. 재검수에서 발견 및 수정한 문제

### 기존 결과의 문제

- 검수 문서의 통과 판정과 달리 장비 상세의 설명문이 상단 요약 카드에
  맞닿아 있었다.
- 장비 상세의 주요 납지 세 번째 행과 대체 관계 안내문이 카드 경계에서
  잘렸다.
- 납품 일정의 우측 상세영역이 화면 하단에 붙었고 카드 내부 마지막 행과
  가정 문구가 잘렸다.
- 변경 신청의 우측 신청 상세, 변경 사유, 처리 과정 내용이 카드 높이를
  초과했다.
- 납품 일정과 변경 신청의 좌측 표는 공백이 과도한 반면 우측 정보는
  지나치게 압축돼 좌우 정보 밀도가 불균형했다.

### 재구성 및 수정

- 제목·설명·요약영역 사이의 수직 간격을 다시 정의했다.
- 모든 본문 카드의 마지막 좌표를 화면 하단에서 최소 24px 안쪽으로
  이동했다.
- 좌측 표의 남는 공간을 선택 항목 수량 요약과 상태 요약으로 사용했다.
- 장비 상세의 우측 카드 높이와 조밀 행 토큰을 재배분했다.
- 납품 일정과 변경 신청의 우측 카드별 내부 여백과 행 높이를 조정했다.
- 화면별 임의 수정 대신 공통 렌더링 소스와 디자인 토큰으로 세 화면을
  다시 생성했다.

### 이전 제작 과정 기록

- 문제: 한글 글꼴 패밀리 이름이 Fontsource 정의와 달라 한글이 네모 문자로 표시됐다.
- 수정: 실제 Fontsource 패밀리인 `Noto Sans KR Variable`로 통일하고 세 화면을 다시 렌더링했다.

### 2차 렌더링

- 문제: 사이드바 하단 접기 아이콘에 공통 크기가 지정되지 않아 크게 표시됐다.
- 수정: 너비와 높이를 18px로 고정했다.

- 문제: 장비 상세의 기본정보와 주요 납지 카드 내용이 다음 카드 경계를 일부 침범했다.
- 수정: 카드별 행 높이, 내부 여백 및 그리드 간격을 재조정했다.

- 문제: 납품 일정 우측 하단의 확인사항이 캔버스 밖으로 잘렸다.
- 수정: 우측 카드 그리드와 조밀형 행 높이를 조정했다.

- 문제: 변경 신청 상세의 처리 과정 마지막 단계가 화면 하단에서 잘렸다.
- 수정: 상세 메타정보를 3열로 구성하고 비교·처리 과정의 여백을 줄였다.

### 최종 재렌더링

- 세 화면을 원본 크기로 다시 열어 텍스트, 카드 경계, 표, 배지 및 하단
  영역을 육안으로 확인했다.
- 모든 카드에 대해 `scrollWidth ≤ clientWidth`,
  `scrollHeight ≤ clientHeight`인지 자동 검사했다.
- 한글 글꼴의 로딩 상태뿐 아니라 `지원장비 김책임` 문자열에 대한 실제
  한글 글리프 사용 가능 여부를 검사했다.
- 화면 전체 요소의 경계 좌표를 검사해 1440×900 캔버스 밖으로 나간
  요소가 없음을 확인했다.
- 세 화면 모두 카드 내부 오버플로 0건, 캔버스 이탈 0건이었다.
- `기준정보 관리`, `사원`, `대리`, `과장` 포함 여부를 검사했으며 모두
  0건이었다.
- 독립 렌더러 구성 중 한글 글리프가 빠진 글꼴 패키지 버전을 발견해
  전체 한글 Subset이 포함된 버전으로 고정하고 세 이미지를 다시 생성했다.

## 8. 남아 있는 가정

- 납품 상태와 진행 단계는 현업 확인 전 임시 값이다.
- 변경 신청의 상태명과 처리 단계는 현업 확인 전 임시 값이다.
- 체계·양산·수출 품번의 관계 유형은 미확정이다.
- 사업별 대체 관계와 대체 방향은 미확정이다.
- 장비 상세의 최종 필수 항목은 마스터 파일 분석 후 확정한다.

## 9. 최종 판정

세 화면 모두 해상도, 공통 프레임, 한글 표시, 색상, 컴포넌트, 금지항목,
카드 내부 오버플로 및 캔버스 경계 검사를 통과했다.
