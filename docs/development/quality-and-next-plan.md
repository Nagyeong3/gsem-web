# 프로토타입 강화 검수와 다음 작업 계획

## 현재 결론

메인 대시보드와 장비 검색은 실제 DB 없이도 Mock Adapter와 Stub API 모드에서 동일한 화면 모델을 사용한다. 실제 HTTP 서버를 통한 Service 통합 테스트까지 통과했으므로 API 경계와 프론트 데이터 변환은 다음 화면 개발의 기준으로 사용할 수 있다.

브라우저 자동 실행은 현재 작업 환경의 운영체제 제한으로 완료하지 못했다. 저장소에 있는 1440×900 라이트·다크 화면 4장을 원본 크기로 별도 검토했으며 프레임 이탈, 가로 잘림, 한글 깨짐, 한자, 금지된 직급은 발견하지 못했다. 이 화면은 Mock 모드 기준이므로 API 모드 최종 시각 검수는 로컬에서 한 번 필요하다.

## 발견하고 조치한 내용

### 날짜와 D-day 불일치 가능성

기존 목업은 특정 날짜를 고정하여 시간이 지나면 납품 예정일과 D-day가 달라졌다. 한국 날짜를 기준으로 예정일을 실행 시점에 계산하도록 변경하고 자동 테스트를 추가했다.

### 빈 검색 결과 페이지네이션

API의 `totalPages: 0`을 화면에서 최소 1페이지로 정규화하여 페이지네이션 오류를 방지했다.

### 의존성 보안 감사

`npm audit --omit=dev`에서 `react-router`의 불안정 RSC API 관련 high 경고가 확인됐다. 현재 프로젝트는 `BrowserRouter`, `Routes`, `Route`만 사용하고 RSC API를 사용하지 않아 해당 공격 경로에 노출되지 않는다. 공식 권고의 수정 버전은 8.3.0이므로 실제 운영 전 호환성 검증을 거쳐 업그레이드한다.

- 공식 권고: https://github.com/advisories/GHSA-qwww-vcr4-c8h2
- 현재 판단: 프로토타입 진행 가능, 운영 전 업그레이드 필수 검토

### 자동 품질 검사 부재

PR마다 같은 검사를 반복할 수 있도록 GitHub Actions를 추가했다. `develop/prototype`과 `main` 대상 PR에서 타입, 린트, 프론트 테스트, Stub 계약 테스트, 빌드를 자동 실행한다.

## 남아 있는 제약

- 현재 작업 환경에서는 Chromium 프로세스가 시작되지 않아 API 모드 Playwright 실행을 완료하지 못했다.
- 실제 로그인, 권한, 실제 DB, 운영 API Host는 범위 밖이다.
- 관리 품목 유형의 DB 저장 위치와 실제 품목 상태 전이는 미확정이다.
- `react-router` 8.3.0 업그레이드는 브라우저 회귀 검수 없이 바로 적용하지 않는다.
- 현재 빌드 산출물은 약 4.7MB이며 대시보드 차트 청크가 크다. 초기 기능 개발을 막는 수준은 아니지만 운영 전 번들 최적화가 필요하다.

## 오늘 이어서 진행할 작업

### 1순위: QA 변경 GitHub 통합

- 별도 QA 브랜치와 PR 생성
- GitHub Actions 실행 결과 확인
- `develop/prototype`에만 병합
- `main`과 release 브랜치는 유지

### 2순위: 장비 통합 상세 페이지 구현 준비

- 기존 장비 검색 상세 패널의 데이터와 전체 상세 화면 필드 매핑
- 상단 요약, 기본정보, 적용정보, 담당자, 납품, 변경이력 Section 구조 확정
- Mock Service와 HTTP Service가 같은 View Model을 사용하도록 설계
- 로딩·빈 값·오류·복수 사업·복수 담당자 인수 조건 작성

장비 통합 상세는 현재 확보한 업무지식만으로도 왜곡 위험이 가장 낮아 다음 구현 화면으로 적합하다.

### 3순위: 납품 일정 화면 구현 명세

- 기간·사업·기종·납지·상태 필터와 표 컬럼 정의
- 예정·진행·완료는 프로토타입 가정으로 명시
- 날짜와 D-day 계산 규칙을 공통 유틸리티로 분리
- 실제 지연 판정과 발주·입고 단계는 미확정으로 유지

### 4순위: 변경 신청 화면은 조회 중심으로 제한

- 신청 목록, 변경 전·후, 처리 과정의 읽기 전용 구조부터 설계
- 실제 승인·반려 버튼과 권한 처리는 구현하지 않음
- 회사에서 처리 상태와 승인 흐름을 확인한 후 기능 확장

## 2차 공개 버전 생성 조건

- GitHub Actions 전체 통과
- 로컬 API 모드에서 대시보드와 장비 검색 수동 확인 1회
- 브라우저 콘솔 오류 없음
- 1440×900 라이트·다크 화면 깨짐 없음
- 공개할 기능 범위를 장비 상세 포함 여부까지 결정

위 조건을 충족한 후 사용자 승인으로 `release/prototype-v2`를 생성한다.
