# 프로토타입 V2 릴리즈 준비도

## 판정

현재 `develop/prototype`는 **2차 공개 후보로 적합**하다. 실제 운영 기능이 아닌 목업 시연본이라는 전제에서 화면 연결, 데이터 구조, 자동검사 기준을 충족한다.

단, `release/prototype-v2` 브랜치는 사용자 승인 전 생성하지 않는다.

## 포함 화면

| 경로 | 화면 | 공개 목적 |
|---|---|---|
| `/` | 메인 대시보드 | 핵심 현황과 업무 진입점 시연 |
| `/equipment` | 장비 검색 | 통합 검색·필터·품목당 한 행 시연 |
| `/equipment/:itemId` | 장비 통합 상세 | 복수 사업·기종·계통·담당자 관계 시연 |
| `/deliveries` | 납품 일정 관리 | 사업·납지별 일정과 수량 비교 시연 |
| `/requests` | 변경 신청 및 처리 현황 | 변경 전·후와 처리 과정 조회 시연 |

## 품질 기준

- TypeScript, ESLint, Vitest, Stub API 계약, 프로덕션 빌드 통과
- Chromium 1440×900 라이트·다크 모드 검사 통과
- 페이지 이동, 검색, 필터, 상세 선택 동작 확인
- 콘솔 오류와 문서 전체 가로 넘침 없음
- 한글 웹폰트 포함, 깨진 한글·한자·일본어 없음
- `김책임` 사용자명 유지, 책임·선임 외 직급 미사용
- `기준정보 관리` 메뉴 미사용
- 실제 회사 데이터와 촬영 자료 미포함

## 공개 시 반드시 설명할 가정

- 대시보드 수치와 모든 품목·담당자·사업·납지 값은 목업이다.
- 납품 상태 `예정·진행·완료` 외 단계와 지연 판정은 미확정이다.
- 변경 신청 상태와 처리 순서는 화면 검증용 가정이다.
- 승인·저장·다운로드·로그인·실제 DB 연동은 동작하지 않는다.
- 품목 유형과 일부 상세정보의 실제 DB 구조는 바뀔 수 있다.

## 릴리즈 생성 전 사용자 확인

- 2차 시연에 장비 통합 상세, 납품 일정, 변경 신청 조회를 모두 공개할지
- 변경 신청 메뉴의 임시 상태값을 시연에서 보여줘도 되는지
- `release/prototype-v2`를 현재 develop HEAD에서 생성할지

위 세 항목을 승인하면 별도 코드 변경 없이 release 브랜치를 생성할 수 있다.
