# 프로토타입 V5 전체 업무 시나리오

## 목적

V5는 실제 DB 없이 사용자가 대시보드에서 품목·납품·변경 정보를 따라가며 전체 업무 흐름을 체험하는 릴리즈다. 데이터 변경은 운영 처리가 아니라 브라우저 메모리의 초안으로만 제공한다.

## 연결된 시나리오

1. 대시보드 핵심 업무에서 납품 일정·변경 신청·장비 검색으로 이동한다.
2. 장비 검색의 검색어·필터·정렬·페이지·선택 상태를 URL에 보존한다.
3. 검색 결과를 키보드로 선택하고 장비 통합 상세로 이동한다.
4. 상세에서 복수 사업·기종·계통·납지를 확인한다.
5. 상세의 품목 식별자를 유지한 채 납품 일정과 변경 신청 내역으로 이동한다.
6. 변경 전·후 비교, 처리 과정과 단종·복수 대체품의 5단계 계보를 조회한다.
7. 잘못된 식별자, 선택 없음, 검색 결과 없음과 조회 오류 상태를 구분한다.

## Mock 역할 차이

| 역할 | 조회 | 변경 신청 초안 | 처리 현황 검토 |
| --- | --- | --- | --- |
| 일반 조회자 | 가능 | 불가 | 조회만 가능 |
| 지원장비 담당자 | 가능 | 브라우저 메모리에서 가능 | 조회 가능 |
| 구매 담당자 | 가능 | 브라우저 메모리에서 가능 | 조회 가능 |
| 승인자 | 가능 | 불가 | 검토 대상 조회 가능 |

역할은 헤더의 `Mock 사용자 역할`에서 전환하며 브라우저 로컬 저장소에만 보존한다. 실제 인증·SSO·권한 판정과 승인·반려는 구현하지 않는다.

## URL 상태

- 장비 검색: 검색어, 기종, 사업, 계통, 장비 구분, 담당자, 납지, 상태, 정렬, 페이지, 선택 품목
- 장비 상세 → 납품 일정: `itemId`
- 장비 상세 → 변경 신청: `itemId`
- 장비 상세 → 변경 이력: `itemId`

직접 URL 이동과 새로고침에서도 조회 조건을 복원한다. URL 값이 잘못되면 안전한 기본값을 사용하거나 찾을 수 없음 상태를 표시한다.

## 프로토타입 가정

- 역할별 화면 차이는 사용성 검증용이며 운영 권한 정책이 아니다.
- 변경 신청 초안은 서버에 전송하지 않고 새로고침하면 사라진다.
- 품목·납품·변경 상태와 처리 순서는 미확정이다.
- 대체 관계의 사업별 유효기간과 실제 승인 흐름은 미확정이다.

## 검증 기준

- TypeScript, ESLint 경고 0건, 단위·계약 테스트와 프로덕션 빌드
- Mock·HTTP API E2E
- 키보드 행 선택, URL 새로고침과 상세 화면 간 이동
- 1440×900 라이트·다크 화면, 콘솔 오류와 가로 넘침
- 실제 회사 데이터·금지 직급·기준정보 관리 메뉴 미포함
- 대시보드 수치 `12 = 3 + 5 + 4`
