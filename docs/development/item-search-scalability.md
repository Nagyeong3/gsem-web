# 품목 검색 확장성 설계

## 결론

품목 검색 조건·정렬·페이징을 Service의 전체 품목 조회 방식에서 `GsemRepository.search_items` 계약으로 이동했다. API와 프론트 데이터 형식은 바뀌지 않는다. 인메모리 구현은 목업 JSON을 검색하지만, 향후 MS Access Adapter는 같은 계약 안에서 DB의 `WHERE`, `EXISTS`, `ORDER BY`와 페이징을 사용할 수 있다.

이번 변경은 실제 DB 성능이 확보됐다는 뜻이 아니다. 현재 ERD와 운영 데이터량이 확정되지 않았으므로 실제 인덱스와 검색 방식은 DB 연결 후 실행 계획으로 검증해야 한다.

## 처리 경계

```text
프론트 검색 조건
  → FastAPI Router의 형식 검증
  → Service의 검색 값 객체 변환
  → Repository.search_items(조건, 정렬, 페이지, 크기)
  → 현재 페이지의 품목 요약과 전체 건수
  → 기존 API 응답
```

Service는 전체 품목 목록을 받지 않는다. Repository가 필터·정렬·페이지 처리를 끝낸 결과만 반환한다. 이 경계 덕분에 실제 DB Adapter가 전체 행을 Python 메모리에 올리지 않아도 된다.

## 인메모리 구현의 한계

- 검색은 전체 목업 품목을 순회하므로 시간 복잡도는 기본적으로 `O(N)`이다.
- 정렬 대상이 M건이면 `O(M log M)`이 추가된다.
- 이는 프로토타입과 테스트용 구현이며 운영 데이터 검색 엔진이 아니다.
- 20,000건 일반화 목업 데이터로 조건 검색, 정렬, 페이지 반환 회귀 테스트를 두되 실제 운영 성능 목표로 해석하지 않는다.

## 실제 MS Access Adapter 구현 원칙

1. 조건에 맞는 `Item.item_id`와 전체 건수를 DB에서 먼저 구한다.
2. 복수 관계 필터는 큰 JOIN 하나보다 `EXISTS`를 우선 검토해 품목 중복을 방지한다.
3. 정렬과 페이지 범위를 DB에서 적용한 후 현재 페이지의 관계 정보만 조회한다.
4. `Integrated_Info`, 계통, 정비계단, 담당자, 납지는 품목별 배열로 집계한다.
5. JOIN으로 늘어난 행 수를 전체 품목 수로 잘못 계산하지 않도록 `COUNT DISTINCT` 또는 별도 건수 쿼리를 사용한다.
6. 한글·영문 대소문자, 공백, NULL, 부분 일치 동작은 실제 Access 드라이버 기준으로 계약 테스트한다.

## 인덱스 검토 후보

아래는 확정 DB 설계가 아니라 검색 실행 계획을 확인할 때의 후보 목록이다.

- `Item.item_num`: 고유 인덱스 유지
- `Item.code_CATEG`, `Item.bender_id`: 단일 조건 사용 빈도에 따라 검토
- `Integrated_Info(item_id, business_id)`: 현재 ERD 주석의 복합 인덱스 확인
- `Match_Item_SubSystem(item_id, code_SSYST)`
- `Match_Item_LevelOfMaintenance(item_id, code_LOM)`
- 담당자 매치 테이블의 `integrated_id`, `user_id`
- `Contract_Delivery`의 `integrated_id`, `delivery_dest_id`, `delivery_status`, 납품일

품명·용도의 `%검색어%` 형태 부분 일치는 일반 B-tree 인덱스를 충분히 사용하지 못할 수 있다. 실제 사용자가 원하는 검색 범위와 데이터량을 확인한 뒤, 품번 전방 일치와 일반 텍스트 검색을 분리할지 결정한다.

## DB 연결 후 필수 검증

- 운영 예상 건수에서 검색어 없음·정확 품번·부분 품명·복수 관계 조건별 응답 시간
- 품목 하나가 여러 사업·계통·납지·담당자를 가질 때 한 행만 반환되는지
- 관계 기준 정렬의 대표값 규칙: 현재 프로토타입은 배열의 첫 번째 이름 사용
- 중복 제거 전후의 전체 건수와 페이지 수
- 한글 정렬과 영문 대소문자 검색 결과
- NULL 관계를 가진 품목의 포함 여부
- 동시 요청과 연결 종료 처리
- 느린 쿼리의 실행 계획과 실제 적용 인덱스

## 미확정 사항

- 운영 품목 수와 동시 사용자 수
- 검색 응답 시간 목표
- 품번·품명·용도 중 검색 우선순위와 정확 일치 우대 여부
- 관계 배열의 첫 번째 값으로 정렬하는 현재 규칙의 운영 적합성
- MS Access 버전, 드라이버와 지원 가능한 페이징 구문
