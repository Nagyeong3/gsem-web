# 실제 DB 연결 체크리스트

## 연결 전에 받아야 할 것

- [ ] 최종 ERD와 테이블 정의서
- [ ] 익명화한 테이블별 최소 1~3개 행
- [ ] PK·FK·Unique Index·Null 허용 여부
- [ ] 공통코드 전체 목록과 사용 여부 값
- [ ] 실제 품목·납품·변경 상태값과 처리 순서
- [ ] Access 파일 형식, 드라이버, 실행 OS와 비트 수
- [ ] 읽기·쓰기 범위와 동시 사용자 수

## 첫 연결 순서

1. 읽기 전용 연결과 상태 확인만 구현한다.
2. `Item` 단건 조회로 필드 타입과 한글 인코딩을 검증한다.
3. `Integrated_Info`를 포함한 복수 사업 품목 한 건을 조회한다.
4. 공통코드 조인과 배열 중복 제거를 검증한다.
5. 납품 날짜·수량·상태를 실제 행과 대조한다.
6. Repository 계약 테스트를 인메모리와 Access에 동일하게 실행한다.
7. 성능·잠금·오류 복구를 확인한 뒤 목록 조회 범위를 넓힌다.

## 반드시 재검증할 항목

- [ ] 품목당 한 행 집계 시 누락·중복 없음
- [ ] 동일 담당자의 사업별 중복 행 제거
- [ ] 담당자 복수 배정과 정·부 표현
- [ ] `delivery_month`, `receipt_month`의 시간대 없는 날짜 처리
- [ ] 예정·진행·완료 코드 변환
- [ ] Null `role`과 누락된 영문명 처리
- [ ] 존재하지 않거나 사용 중지된 공통코드 처리
- [ ] 대체품이 여러 단종품을 대체하거나 여러 갈래로 분기되는 관계
- [ ] 검색·정렬·페이징의 DB 처리 결과와 인메모리 결과 일치
- [ ] 한글 정렬 순서와 대소문자 검색 규칙
- [ ] Access 파일 잠금, 타임아웃, 재시도 및 읽기 일관성
- [ ] 로그에서 실제 개인정보와 업무 데이터 마스킹

## 연결 후에도 별도 승인이 필요한 범위

실제 로그인·SSO, 운영 권한, 변경 승인·반려, 자료 Import, 쓰기 트랜잭션과 운영 배포는 DB 연결과 별개의 후속 범위다.
