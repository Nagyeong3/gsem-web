# 프로토타입 V4 릴리즈 검수 결과

## 릴리즈 목적

V4는 신규 업무 기능을 늘리는 릴리즈가 아니라 전체 조회 UX를 안정화한 기준본이다. 여섯 화면이 같은 조회 상태 모델과 Mock·HTTP 전환 구조를 사용하도록 고정하고, 이후 업무 시나리오 개발의 안전한 출발점으로 사용한다.

- TypeScript 검사: 통과
- ESLint: 경고 0건 통과
- Vitest: 13개 파일, 33개 테스트 통과
- OpenAPI·Stub API 계약: 18개 테스트 통과
- 프로덕션 빌드: 통과

- HTTP API 모드 Playwright: 전체 조회 시나리오 1개 통과
- 대시보드 핵심 업무 수치: `12 = 3 + 5 + 4` 통과

## 화면 검수

- 여섯 화면을 라이트·다크 모드로 각각 캡처해 총 12장을 확인했다.
- 모든 이미지는 1440×900이며 공통 사이드바 176px, 헤더 58px를 유지한다.
- 가로 넘침, 요소 잘림, 깨진 한글, 금지 직급, `기준정보 관리` 메뉴 및 실제 사내 데이터가 없다.
- 장비 통합 상세의 세로 스크롤은 정보량에 따른 정상 동작이다.

## 발견 및 수정

- 개발 서버에서 React Flow와 차트가 동시에 크기를 다시 계산할 때 Vite 개발 클라이언트가 `ResizeObserver` 알림을 오류처럼 기록하는 현상을 확인했다.
- 오류를 숨기지 않고 실제 사용자에게 제공할 프로덕션 빌드를 Playwright가 검증하도록 실행 구조를 바꿨다. Mock·HTTP 모드 모두 프로덕션 미리보기 서버를 사용한다.
- 실행 환경의 npm 기본 캐시 권한 제약은 프로젝트 문제가 아니므로 임시 캐시로 의존성을 설치해 검증했다.

## 프로토타입 가정과 미확정

- 품목·납품·변경 상태값과 처리 순서는 운영 규칙이 아닌 프로토타입 가정이다.
- 담당자 정·부 구분, 관리 품목 유형 저장 위치, 지연 판정 규칙은 미확정이다.
- 실제 DB, 로그인, 승인·반려, 운영 배포는 포함하지 않는다.

## 최종 판정

조회 UX, 데이터 접근 경계, 라이트·다크 화면과 자동 검증이 V4 릴리즈 기준을 충족한다. `release/prototype-v4`는 이 검수 결과가 병합된 `develop/prototype` 커밋에서 생성한다.
