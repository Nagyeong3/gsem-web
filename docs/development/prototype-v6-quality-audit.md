# 프로토타입 V6 전체 품질 감사

## 결론

V6은 실제 DB 연결 전 통합 준비본으로서 프론트 조회 흐름, 인메모리 백엔드, API 계약과 Mock/API 전환을 시연할 수 있다. 이번 감사에서 기능을 대폭 변경하지 않고 검색 재조회, 요청 추적, 브라우저 검증 경로와 동작 상태 회귀검사를 보강했다.

실제 MS Access, 인증·SSO, 운영 승인, 운영 권한과 배포는 여전히 검증 범위가 아니다.

## 감사 범위

- 대시보드
- 장비 검색과 통합 상세
- 납품 일정 관리
- 변경 신청 및 처리 현황
- 5단계 장비 변경 이력
- 라이트·다크 모드
- Mock Service와 HTTP API Adapter
- Repository–Service–Endpoint 경계
- OpenAPI 계약, 오류 응답, CORS와 요청 ID
- TypeScript, ESLint, 테스트, 빌드와 브라우저 콘솔
- 공개 저장소용 목업 데이터와 금지 항목

## 발견하고 수정한 문제

| 구분 | 발견 내용 | 수정 내용 | 결과 |
|---|---|---|---|
| 검색 UX | 장비 검색의 `검색` 버튼이 별도 재조회 동작을 수행하지 않음 | 버튼에 현재 조건 재조회 동작 연결 | 통과 |
| 접근성 | 선택한 검색 결과 행의 선택 상태가 보조기술에 명시되지 않음 | `aria-selected` 추가 | 통과 |
| 안내 문구 | 일부 문구가 V6에서도 `1차 프로토타입`으로 표시됨 | 현재 프로토타입 기준 표현으로 통일 | 통과 |
| API 추적 | 개발 CORS에서 `X-Request-ID` 송수신 허용·노출이 완전하지 않음 | 허용·노출 헤더 추가 | 통과 |
| API 방어 | 클라이언트 요청 ID를 길이·문자 제한 없이 로그와 응답에 사용함 | 영문·숫자·일부 기호, 100자 이내만 허용하고 나머지는 UUID로 교체 | 통과 |
| 브라우저 검증 | 기본 캐시 외 Chromium 실행 경로를 지정할 수 없음 | 선택형 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 지원 | 통과 |
| 화면 증적 | 기본 12장 외 필터·오류·권한 등 동작 상태 증적이 없음 | 동작·예외 상태 19장과 자동검사 추가 | 통과 |
| CI 증적 | 하위 폴더의 동작 캡처가 Actions 산출물에서 누락됨 | 캡처 경로를 재귀 패턴으로 변경 | 통과 |

## 화면 검수 기준

- 사이드바·헤더·콘텐츠 시작 위치와 공통 프레임 유지
- 페이지 제목, 본문, 표, 입력 필드와 상태 배지의 디자인 토큰 유지
- 라이트·다크 모드에서 텍스트 대비와 선택 상태 확인
- 필터, 정렬, 페이지, 선택, 역할, Dialog, Snackbar 표시 확인
- 로딩, 오류, 재시도, 빈 결과와 잘못된 식별자 확인
- 장비 변경 이력의 5단계, 분기와 복수 사업 표시 확인

## 보안 의존성 검토

`npm audit --omit=dev` 결과 `react-router`의 RSC Mode Action 관련 고위험 권고 1종이 `react-router-dom` 경유 2건으로 집계된다. 현재 GSEM은 RSC Mode나 React Router Action Endpoint를 사용하지 않는 Vite SPA이므로 해당 공격 경로는 사용하지 않는다. 감사 시점의 `react-router-dom` 7 계열에는 적용 가능한 상위 패치가 없어 무리한 메이저 교체나 임의 하향은 하지 않았다.

실제 인증·서버 Action을 도입하기 전에는 다음을 다시 수행한다.

1. React Router 보안 패치 제공 여부 확인
2. RSC·Action 도입 여부에 따른 영향도 재평가
3. 실제 인증과 CSRF 방어 정책 검증

## 남아 있는 제약과 프로토타입 가정

- 실제 DB의 스키마, 데이터 품질, 동시성, 파일 잠금과 트랜잭션은 확인하지 않았다.
- 납품 상태 `예정·진행·완료`와 변경 처리 순서는 프로토타입 가정이다.
- 담당자는 품목 단위로 해석하되 정·부 구분의 실제 DB 반영은 미확정이다.
- 관리 품목 유형의 실제 저장 위치는 미확정이다.
- 실제 로그인, 조직 권한, 승인·반려, 엑셀 다운로드와 운영 배포는 구현하지 않았다.

## 실행 명령

```bash
npm ci
npm run typecheck
npm run lint
npm run test
npm run test:stub
npm run test:server
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:e2e:api
```

브라우저 캐시 위치가 제한된 환경에서는 다음처럼 실행 파일을 지정할 수 있다.

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/브라우저/경로/headless_shell npm run test:e2e
```
