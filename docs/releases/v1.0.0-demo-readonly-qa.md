# GSEM 1차 운영 데모 — 읽기 전용 안정화 QA

## 확정 범위
- SQL Server 데이터 조회만 진행. DB 쓰기·담당자 변경 저장·감사 로그 추가 **미포함**.
- 지원장비 통합현황에서는 LAH 2차 PBL만 활성화하고 나머지 사업은 추후 오픈 예정(프론트 제한).
- 승인·반려·단종대체 검토 요청 UI/라우트 미제공. 기존 단종·대체 관계 조회 화면은 보존.
- 기존 서버 경로와 `/equipment`, `/equipment-master`, `/deliveries`, `/history` URL 유지.

## 테스트 범주

1. 라우팅/메뉴: 대시보드, 통합현황, 검색, 장비상세, 납품, 변경이력, 제거한 /requests 폴백.
2. 장비 검색: Enter 검색 확정, 조건 칩 X 삭제, 초기화, 상세 선택, 페이지/정렬.
3. 통합현황: 자동 검색, 한글 조합, 사업/조달원/바이어 필터, 엑셀/최적화 탭, 페이지네이션, CSV, 스크롤, 컬럼 폭 조절/저장.
4. 이력: 조회·상세 경로, 단종/대체 그래프. **DB 수정 로그 기능은 구현하지 않음**.
5. 예외 상태: 빈 결과, 오류·재시도, 없는 장비 ID, 이미지 없을 때의 대체 표시.
6. 디스플레이: 1280×900, 1440×900, 1920×900에서 주요 6개 라우트의 페이지 전체 가로 넘침과 JS 예외 확인.
7. 내부 배포: `dist/index.html`, 자산 경로, port 4173, React Router 직접 URL 접속/새로고침.

## 운영 서버 명령
```bat
cd /d C:\GSEM-WEB
python tools\serve_spa.py --port 4173 --host 0.0.0.0
```
Python 명령이 작동하지 않을 때는 `py tools\serve_spa.py --port 4173`을 사용. 프로젝트 경로를 실제 위치로 바꾸고, 먼저 개발 서버에서 `npm run build`로 dist를 생성할 것.
정적 HTTP 서버는 내부 시연용이며 TLS/인증/보안 프록시 기능을 제공하지 않음. DB API와 프론트 정적 서버는 별도.

## 배포 차단 기준
- GitHub Actions: 타입 검사, lint, 단위/API 테스트, 프론트 빌드, Chromium 브라우저 시나리오 모두 성공.
- 운영 환경: 해당 사업을 정확히 인식하고 **LAH 이외 데이터가 표시되지 않음**; 조회·다운로드·이미지 API가 정상; URL 직접 접속/새로고침 정상; 실제 SQL Server 인증 및 연결.
- 다른 사업의 백엔드 접근을 서버 수준에서 차단해야 하는 요구가 있으면 **프론트 사업 필터만으로는 불충분**하므로 별도 조치 필요.
- 기존 이력 화면은 기존 관계 데이터 기반이며 '누가 직접 어떤 필드를 수정했는지'라는 DB 감사 기록이 아님.
