# GSEM v0.9.0 — 폐쇄망 전체 소스 동기화 및 검증 안내

대상 브랜치: `feature/main-workflow-page`

## 패키지 원칙

- 현재 브랜치에 Git 추적된 전체 소스를 **단일 ZIP**으로 받습니다.
- `node_modules/`, `wheelhouse/`, `.venv/`, `venv/`, `dist/`, `build/`, `.git/`, `.env`, `.env.*` 중 실제 비밀 환경설정, `__pycache__/`, `*.pyc` 파일은 포함하지 않습니다.
- `.env.example`은 설정 예제이므로 포함합니다. 접속 암호, 실제 DB 정보, API 키를 Git에 넣지 마세요.
- 기존 폐쇄망 폴더를 덮어쓰기보다 **새 디렉터리로 압축 해제 후 전환**하세요. 구조 불일치로 남아 있는 오래된 파일이 실행되는 문제를 방지합니다.

## CMD — 폐쇄망 새 프로젝트 폴더 구축

1. 기존 개발 서버를 종료합니다.
2. 현재 사용 중인 `GSEM-WEB` 디렉터리를 별도의 이름으로 **통째로 보관**합니다. 특히 `.env`, `backend/.env`, `node_modules`, `.venv`, `wheelhouse`, 로그 및 데이터 파일은 삭제하지 않습니다.
3. 전달받은 `GSEM_v0.9.0_FULL_SOURCE.zip` 파일을 새 폴더에 압축 해제합니다. ZIP에는 저장소 파일 전체가 들어 있습니다.
4. 필요할 경우 기존 폴더에서 새 폴더로 `.env`만 복사하고 DB 연결 설정을 확인합니다. `node_modules` 또는 `.venv`를 재사용한다면 버전/경로 호환성을 검사하고, 가능하면 준비된 오프라인 패키지로 재설치합니다. `wheelhouse`는 기존 폴더에서 별도 보관해도 됩니다.
5. 프로젝트 루트 CMD에서 순서대로 실행합니다.

```bat
node --version
npm --version
npm run typecheck
npm run build
python -m compileall -q backend
```

프론트 구동:
```bat
npm run dev -- --host 0.0.0.0
```

FastAPI는 프로젝트 `.env`와 기존 명령어를 사용해 실행합니다. 실제 DB는 GitHub Actions에서 연결할 수 없으므로 폐쇄망에서만 테스트할 수 있습니다.

## 필수 점검

- 사이드바 통합현황/장비 검색 메뉴 동시 선택이 발생하지 않음
- 장비 검색 검색어 필터 X를 클릭하면 URL 필터와 검색창이 함께 초기화됨
- 장비 검색의 Enter/한글 IME/목록 스크롤과 행 선택 유지
- 통합현황의 550ms 자동 검색과 검색 중 테이블 보존
- 통합현황 열 크기 조정·더블클릭 자동 맞춤 및 새로고침 후 너비 복원
- 통합현황 사업/조달원/바이어 필터, CSV 저장, 계약/납품 상세
- 대시보드 지표·차트·최근 변경 이력, 메뉴 이동
- 실제 장비 이미지가 아직 없으면 이미지 조회만 보류

## 빌드와 데이터 검증 차이

GitHub CI: TypeScript, ESLint, 프론트 단위 테스트, OpenAPI, FastAPI Mock 테스트, Playwright, 정적 빌드를 검사합니다.
폐쇄망: SQL Server 실DB 검색, 실제 이미지, 내부 네트워크 및 DB 설정을 최종 확인합니다.

## 롤백

새 폴더에서 문제가 발견되면 서버를 종료한 뒤 기존 백업 폴더를 다시 실행합니다. DB 스키마는 이 소스 동기화 과정에서 변경하지 않습니다.

## GitHub 소스 ZIP

GitHub 브랜치 화면 > Code > Download ZIP (또는 릴리스/CI에서 제공하는 ZIP).
ZIP에 `package.json`, `package-lock.json`, `src/`, `backend/`, `docs/`, `tools/`, `e2e/`가 모두 있는지 확인합니다.
