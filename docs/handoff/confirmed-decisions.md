# 확정·가정·미확정 기준

## 확정

- 시스템 가칭은 `지원장비 관리시스템 (GSEM)`이다.
- 검색 결과는 품목 하나당 한 행으로 표시한다.
- 한 품목은 여러 사업, 기종, 계통, 정비 계단과 납지를 가질 수 있다.
- 담당자는 품목 단위로 배정하며 한 품목에 여러 명이 배정될 가능성을 고려한다.
- `Item.code_CATEG`는 `CATEG` 공통코드 그룹을 참조하는 장비구분이다.
- `ATYPE`은 기종, `LOM`은 정비계단, `SSYST`는 계통 공통코드 그룹이다.
- `delivery_month`, `receipt_month`에는 `YYYY-MM-DD` 날짜가 들어간다.
- 납품 상태의 업무 의미는 예정·진행·완료다.
- 로그인 표시 사용자는 `김책임`, 직급은 책임·선임만 사용한다.
- 실제 회사 데이터는 저장소에 넣지 않는다.

## 프로토타입 가정

- 대시보드 지표는 일반화한 고정 목업값이다.
- 확인이 필요한 업무는 `12 = 지연 3 + 대체 검토 5 + 승인 대기 4`다.
- 품목·변경 처리 상태와 처리 순서는 화면 검증용 값이다.
- 담당자 정·부 표시는 화면 확장성 검증용이며 DB 저장 필드는 없다.
- 복수 관계 열 정렬은 배열의 첫 번째 이름을 대표값으로 사용한다.
- 변경 신청 초안은 브라우저 메모리에만 저장한다.
- 지연 여부를 날짜만으로 자동 판정하지 않는다.

## 미확정

- 관리 품목 유형의 최종 DB 저장 위치
- 최종 ERD, NULL, PK·FK·Unique와 공통코드 전체 목록
- 실제 품목·변경 상태값과 상태 전이
- 담당자 정·부 및 역할 코드 저장 방식
- 사업별 대체 관계와 적용 시작·종료일
- 대체 관계의 최종 물리 테이블
- 납품 지연 판정 규칙
- 운영 역할별 조회·수정·승인 권한
- 실제 인증·SSO와 사내 메일 연동 방식
- 운영 데이터 규모, 동시 사용자와 검색 응답 시간 목표

## 단종 문의 기능

업체에 단종 여부를 주기적으로 문의하고 회신을 관리하려는 수요는 확인됐으나 상세 요구사항은 미확정이다. 다음을 확인하기 전 자동 메일 발송을 구현하지 않는다.

- 점검 주기와 점검 대상 선정 기준
- 제조사·구매처 중 실제 문의 대상
- 업체 담당자 이메일의 관리 위치
- 문의 완료와 회신 결과의 상태값
- 단종 회신 후 대체품 검토 연결 흐름
- 사내 메일 API, Exchange·Graph 또는 SMTP Relay 사용 승인

우선 구현 후보는 `내 담당 품목 단종 점검 목록 → 메일 문안 생성 → 문의·회신 결과 수동 기록`이다.
